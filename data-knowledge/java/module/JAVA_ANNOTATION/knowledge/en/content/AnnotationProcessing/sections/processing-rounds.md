Annotation processing happens in **rounds**. The compiler starts with the source types being compiled, runs applicable processors, and may receive new source/class files generated by those processors. Generated source can introduce new annotated elements, which leads to another round.

```text
initial source files
        ↓
round 1 processors run
        ↓
generated source/class files?
        ↓ yes
round 2 sees new roots
        ↓
more generated files?
        ↓
...
        ↓
final round: processingOver() == true
```

A processor receives a `RoundEnvironment` for each invocation:

```java
if (roundEnv.processingOver()) {
    // final-round cleanup/reporting if needed
}
```

`roundEnv.errorRaised()` also lets a processor observe whether an error was raised in the prior round.

### WHY — processors must tolerate repeated invocation

Do not write a processor as though `process(...)` runs exactly once. Generation in one round can cause more rounds, and the final round has different conditions from normal discovery rounds.

State kept inside a processor instance should therefore have deliberate lifecycle semantics and must not cause the same file to be generated repeatedly.
