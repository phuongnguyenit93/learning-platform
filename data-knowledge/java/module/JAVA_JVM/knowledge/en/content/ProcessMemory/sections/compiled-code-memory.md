Machine code generated by the JIT compiler requires executable process memory. HotSpot manages this through code-cache-related structures.

Compiled-code memory can grow as the runtime profiles and compiles more methods. It is not ordinary Java object heap.

```text
warm-up
→ more compilation
→ more generated native code
→ process memory may increase
```

This helps explain why a service may have a larger RSS after several minutes even when its live heap is similar to startup.

Measuring code-cache/compiler pressure belongs to diagnostics tooling.
